# Українська переписка — sillytavern-ua-v3

Гілка: `feat/sillytavern-ua-2026-10-04`. База: `f42df545b35b75a07362a4385a34f085082a5dee`.

## Проблема і зміни

У живій перевірці v2 на «Хочу розвіятись» модель видала непідтверджені цікавинкі. На питання про тривожність `BookGroundingGuard` відкинув приховану цитату й сам надіслав сирий книжковий уривок. Передача трьох прикладів і PHI працювала, але якість діалогу користувач відхилив.

У v3:

- Автоматичної підстановки уривка більше немає. Вимогу прихованої дослівної цитати прибрано з активного маршруту.
- Звичайний чат повертає текст. Книжковий запит повертає `kind`, `reply`, `source_ids` у тій самій генерації. У Telegram потрапляє тільки `reply`.
- `clarify` дозволяє поставити доречне уточнення без книжкового посилання та без обов’язкової вправи. Позначка очікуваного уточнення зберігається локально в наявному ConversationState. Відповідь на питання знову підключає книжковий контекст. Попередні дані не видаляються.
- `answer` пояснює своїми словами матеріал із переданих джерел; ID зберігаються в метаданих. `insufficient` позначає брак підстав для відповіді. `conversation` дозволяє відмову чи зміну теми.
- Перевіряються формат, ID, порожня відповідь, довге дослівне копіювання та непідтверджені цифрові параметри. Числа з повідомлень користувача можна повторити; номери пунктів списку не вважаються параметрами вправи.
- За помилки є максимум одна додаткова генерація з конкретною причиною відхилення. Вона використовує той самий контекст. Якщо перевірка знову не пройшла, застосовується наявна обробка недоступної відповіді; сирий уривок не відправляється.
- Каталог фактів підключається на явне прохання про факти чи продовження попереднього факту. Запити поговорити, розвіятись або змінити тему його не активують. Без збігу теми випадкові елементи не підставляються.
- Українська картка переписана навколо конкретного внеску в розмову, доречної ініціативи, прийняття відмови та уточнень. Чотири авторські приклади займають 670 оцінених токенів при ліміті 700. Це приклади прийомів, а не відповіді для копіювання.
- `temperature=0.8`, `top_p=1`. Це налаштування варіативності, не доказ фактичності чи поліпшення стилю.

## Книжковий пошук

Пошук лишається локальним лексичним пошуком у наявній PostgreSQL-базі. Embeddings, семантичний reranker і NLI-перевірка не підключалися.

Мета питання зберігається окремо від стоп-слів: «Як побороти тривожність?» активує практичний добір, хоча BM25 шукає тематичні слова. Для практичного запиту пріоритет мають тематично відповідні уривки з ознаками вправ/кроків. Для пояснення поняття цей пріоритет не застосовується. Попередній відбір лише 256 уривків за частотою слова прибрано; ранжується весь набір тематичних збігів активних книг. Це розраховано на невелику імпортовану бібліотеку; зростання корпусу потребуватиме окремої оптимізації пам’яті та пошуку.

Вибір вікна уривка враховує сусідні речення, щоб назва способу й пояснення не губилися через межу речення. Текст лишається суцільним оригінальним фрагментом, з якого модель формує переказ. Ознаки практичного тексту — евристика, а не доказ доречності. Генератор має оцінити, чи уривок дійсно відповідає на питання, та може уточнити ситуацію або визнати недостатність матеріалу.

Формат індексу, таблиці та імпортер не змінювалися. Переімпорт книг і міграція даних для цього оновлення не потрібні.

## Підстави для промпта і межі доказів

1. [SillyTavern Prompts](https://docs.sillytavern.app/usage/prompts/) — роль історії, прикладів і post-history instructions. Використано механізми наявної C#-адаптації SillyTavern 1.19.0, а не додатковий процес Node.js.
2. [Smith et al., 2020: BlendedSkillTalk](https://aclanthology.org/2020.acl-main.183/) — дослідження поєднання емпатії, знань та залученості в діалозі.
3. [Roller et al., 2021: Recipes for Building an Open-Domain Chatbot](https://parl.ai/projects/recipes/) — людська оцінка багатокрокової розмови; баланс слухання, внеску в тему, питань і відповідей.
4. [Groq Structured Outputs](https://console.groq.com/docs/structured-outputs) — strict JSON Schema для поточних GPT-OSS і Qwen 3.8. Схема гарантує форму, а не правдивість тексту.
5. [ALCE](https://github.com/princeton-nlp/ALCE) — підтримка твердження джерелом оцінюється окремо від наявності посилання. Автоматичної семантичної перевірки з цієї роботи в боті немає.

Роботи BlenderBot/BST стосуються навчених моделей, переважно англомовних. Їхні результати не доводять ефективність конкретного українського промпта на GPT-OSS. Тексти датасетів не імпортувалися: наші приклади написані окремо та не видаються за реальні користувацькі діалоги. Наявність правильного source_id не доводить, що кожне твердження відповідає джерелу. Перевірка числа також не підтверджує його зміст. Нуль вигадок не гарантовано.

## Контекст, виклики та експлуатація

Збережені довготривала пам’ять, історія, згода на настрій, версії очищення пам’яті, Telegram/outbox і збирання серії повідомлень. Окремого виклику для планування чи оновлення ConversationState немає. Звичайний успішний хід — один виклик Groq; початкове просте привітання — локальне `first_mes`. Книжковий хід теж один, крім явно відхиленої відповіді та технічних повторів API. Фонові підсумки збережені.

У бюджеті заздалегідь враховано книжкову інструкцію та схему. Метадані не потрапляють у видимий текст чи в історію як додаткова репліка. Логи містять версію, формат, тип книжкової відповіді, ID уривків і причини відхилень; приватні повідомлення та уривки в консоль не записуються.

Для встановлення з поточної гілки зупинити Run, виконати:

```bash
git pull --ff-only origin feat/sillytavern-ua-2026-10-04
```

Потім запустити Run. Очікувана версія в `Friend exchange`: `sillytavern-ua-v3`.

## Перевірка цього оновлення

Основний проєкт збирається в Release без помилок і попереджень. JSON-ресурси прочитані, бюджет усіх чотирьох блоків прикладів перевірений. `git diff --check` проходить. Тести не запускалися й не додавалися, згідно з вказівкою користувача.

Ключа Groq та робочої БД у середовищі виконання немає. Живі відповіді, якість пошуку по фактично імпортованих книгах і затримки Telegram не перевірені. Жодні написані вручну приклади не подаються як результати моделі. V3 виправляє підтверджені помилки коду; природність і надійність кінцевих відповідей потребують живої перевірки.
