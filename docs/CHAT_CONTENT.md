# SillyTavern UA v2 — 04.10.2026

Гілка `feat/sillytavern-ua-2026-10-04`, база `feat/friend-dialogue-2026-10-04` (`5e3c7c55888ea879539431f95efe73b809b96115`).

## Чому v1 не пройшла живу перевірку

Користувач перевірив v1 у Telegram і відхилив якість: недоречний жарт після скарги на день, порада замість виправлення незрозумілої репліки, нові пропозиції після відмови. Логи `sillytavern-ua-v1` / `structuredTurn False` підтверджують активний маршрут. У наведеній розмові книжкових уривків немає, що відповідає відсутності прохання про конкретну психологічну допомогу.

Під час перегляду коду виявлено:

- У картці були три example blocks, але ліміт 600 оцінених токенів постійно пропускав лише перші два. Приклад прийняття відмови був третім і не потрапляв у запит. Приклади, що лишалися, та опис голосу наголошували на іронії. Це підтверджене зміщення вхідного контексту, а не доказ єдиної причини всіх невдалих відповідей.
- PHI фактично переносилася в початковий system-блок під час `GroqMessageLayout.Prepare`. Вона більше не була після історії, хоча цей порядок є окремим механізмом SillyTavern.
- `ConversationState.last_action` повторював останню відповідь ще й у system/reference-контексті поряд із дослівною історією. Невдала відповідь отримувала зайве повторення.

У v2 PHI лишається після реального чату через user-role fallback, який описаний у [документації SillyTavern](https://docs.sillytavern.app/usage/prompts/). Картка містить три компактні вигадані блоки: відгук і прийняття відмови, виправлення свого нерозуміння, доречна відповідь на жарт. Увесь набір займає 413 оцінених токенів із сепараторами. Картка, що перевищить 600, відхиляється при завантаженні, щоб обрізання не лишалося непомітним.

Короткий state зберігається й використовується для продовження книжкового запиту. У текстовий запит він додається тільки тоді, коли відповідний обмін не включено до дослівної історії. Повна історія та джерела продовжують зберігатися в БД.

Перенесене складання запиту не навчає модель нового характеру. Картка й PHI залишаються нашими налаштуваннями; їхня жива українська якість у v2 ще не підтверджена. Невдалий результат v1 не приховується за успішною збіркою.

## Що саме адаптовано

Прочитано вихідний код SillyTavern **1.19.0**, release commit `06bde939fb1e9c4c8d8641d810f0a916b5bce127`. У C# перенесено механізм текстового one-to-one Chat Completion: колекції повідомлень і бюджет, формування визначень персонажа, порядок marker-блоків, character-specific main/PHI overrides, шаблони personality/scenario, початок чату та включення цілих блоків прикладів. Відповідність конкретним upstream-функціям і точні посилання є у [third_party/SillyTavern/NOTICE.md](../third_party/SillyTavern/NOTICE.md).

Це адаптоване ядро складання запиту для нашого Telegram-транспорту, а не запущений вебінтерфейс SillyTavern. Повний браузерний рушій, групові чати, медіа, інструменти й довільні ST-extensions не вбудовувалися. Node.js і встановлення SillyTavern у Replit для цього шляху не потрібні.

## Активний шлях

1. Наявний `ConversationMemory` читає історію, довготривалу пам'ять, стислий запис попереднього обміну та явно висловлені побажання. Застосовує попередні перевірки сесії, версії пам'яті й дозволу на настрій.
2. Локальний книжковий добір, каталог фільмів і довідкових фактів за потреби додають матеріал. Виправлений пошук «Як побороти тривожність?» збережено. Лексичний добір не гарантує розуміння будь-якого перефразування.
3. `TavernPromptBuilder` складає визначення й обов'язкові блоки за preset-порядком, резервує початок чату, додає історію від найновішої репліки та цілі блоки прикладів. Поточне повідомлення має вміститися цілим; старіші можуть не ввійти.
4. Groq повертає **звичайний текст**. В активному чаті немає `friend_turn_plan`, `friend_exchange` або окремого виклику для запису пам'яті. Старі `CompleteTurn`/JSON helpers лишилися для сумісності неактивних інтерфейсів; `ChatResponder` їх не викликає.
5. Перед доставкою перевіряються книжкові позначки, прибираються службові маркери й формуються наявні метадані джерел. Спостережуваний запис продовження складається локально з фактично отриманого повідомлення та фактично надісланої відповіді.

Попередній `DialoguePlanner` і його payload вилучені. Старі `GROQ_PLANNER_MODEL`, `AI_DIALOGUE_PLANNING`, `AI_PLANNER_TIMEOUT_SECONDS` більше не читаються; у Secrets їх можна залишити, вони не активують попередній шлях.

## Preset і персонаж

- `src/Bot/Resources/Conversation/sillytavern-ua.json` створено з незміненого upstream `Default.json`, збереженого в `third_party/SillyTavern/Default.upstream.json`. Збережені структура й порядок `prompt_order`. Змінено провайдера/модель, українські тексти, контекст і вихідний бюджет; `enhanceDefinitions` лишається вимкненим.
- `friend-character.json` — власна українська Character Card V2. Підтримуються `description`, `personality`, `scenario`, `first_mes`, `mes_example`, `system_prompt`, `post_history_instructions`; макроси `char`, `charIfNotGroup`, `user`, `personality`, `scenario`, `description`, `original`.
- Короткі вигадані приклади манери передаються як ST named-system examples зі speaker-prefix. Це не імпортований Style Bank і не повідомлення поточного користувача. Довготривала пам'ять їх не читає. Приклади обмежені 600 оціненими токенами; блоки не обрізаються посеред діалогу.
- `pin_examples=false`: як у стандартному ST-шляху, історія пакується раніше прикладів, але у вихідному порядку приклади стоять перед реальною історією. На етапі читання пам'яті резервується розмір усього компактного набору. Службові блоки та їхні обгортки рахуються за фактичним вмістом, замість додавання довільних 120 токенів.
- Якщо це перша проста репліка-привітання в поточній сесії, доставляється саме `first_mes`: **`привіт)`**. Модель цей текст не перегенеровує. За наявної історії або іншого прохання використовується звичайний шлях.

Пам'ять й уривки підключаються як literal reference data у `worldInfoBefore`/`worldInfoAfter`. Макроси на цих даних не виконуються. Початкові instruction/example blocks збираються в один system-блок: [reference template GPT-OSS](https://huggingface.co/openai/gpt-oss-120b/blob/main/chat_template.jinja) витягує лише початковий system/developer message, а подальший цикл рендерить assistant/user/tool. PHI тепер має роль user і службову обгортку та лишається після реальної історії, як ST fallback для API без пізнього system. Це інструкція застосунку з `IsApplicationPrompt=true`, а не записана репліка користувача. У Groq передаються тільки role/content. Визначення поточного прохання, оцінка бажаної довжини й логи пропускають службову ін'єкцію. Справжні репліки зберігають вміст і порядок; додаткова ін'єкція не записується до історії чи довготривалої пам'яті.

## Книжкова порада

Недостатньо отримати уривок і довірити моделі довільну вправу. Для прямого запиту психологічної допомоги:

- модель має додати `{{book:ID|дослівна цитата}}`, щонайменше 20 символів цитати;
- ID має належати реально переданому уривку, а цитата — бути його підрядком після нормалізації Unicode, пробілів, апострофів і тире;
- цифрові параметри й послідовності у видимій відповіді мають бути в підтверджених цитатах. «4‑7‑8» нормалізується й перевіряється як числова послідовність, а не приймається через сам факт наявності будь-якої книги;
- якщо перевірка не пройшла, запропонований текст не доставляється: повертається справжній уривок із джерелом у внутрішніх метаданих. Якщо матеріалу немає — коротке чесне повідомлення про відсутність підтвердженого способу;
- цитати-маркери та ID прибираються перед Telegram; назви і сторінки доступні на пряме запитання про походження.

Ці перевірки доводять наявність цитати та підтримку цифрових параметрів. Вони не доводять семантичної правильності будь-якого перефразування, доречності уривка до життя людини або чисел, написаних словами. Повноцінного LLM-judge, окремої генерації методів і нового переліку заборонених технік немає. Прямий уривок у резервному випадку може звучати книжково; це свідомий вибір проти доставки непідтвердженої вправи.

Імпортовані книги, індекси й лексичний пошук збережені. Повторний імпорт не потрібний.

## Пам'ять, виклики й доставка

Схему БД та міграції не змінено. Старі semantic `ConversationState` продовжують читатися. Нові записи зберігають поточну тему/запит, явні вподобання, фактичну останню відповідь і останню реакцію; це локальний спостережуваний запис, а не нова модельна інтерпретація потреб. Короткі очевидні продовження утримують попередню тему. Поточне відкрите прохання визначається з дослівної історії, а не з вигаданого локального `pending`.

Довготривала пам'ять і фонові підсумки працюють через наявні компоненти; очищення, згода й `MemoryVersion` збережені. Хеш реально доставленої відповіді визначає чинність метаданих. Перерване повідомлення не стає фальшивим повним обміном.

Успішна звичайна репліка — один виклик `openai/gpt-oss-120b`; перше просте привітання — нуль. Пошук книжок і перевірка цитат локальні. Основна генерація зберігає технічні повтори та резервну модель, тому під час збоїв HTTP-запитів може бути більше одного. Фонові підсумки, як раніше, окремі. Telegram/outbox та збирання серії повідомлень збережені.

Налаштування sampler взято з preset: `temperature=1`, `top_p=1`. Вихідний бюджет 2048 враховує приховане reasoning. Нових платних сервісів, одержувачів даних чи пакетних залежностей немає. Облік токенів використовує оцінку нашого бота, а не браузерний tokenizer ST; квоти Groq мають перевагу над великим контекстом моделі.

## Запуск у Replit

Зупини Run. У Shell:

```bash
git fetch origin feat/sillytavern-ua-2026-10-04
git switch -c feat/sillytavern-ua-2026-10-04 FETCH_HEAD
```

Якщо вже працюєш у цій гілці, для оновлення v1 → v2:

```bash
git pull --ff-only origin feat/sillytavern-ua-2026-10-04
```

Потім натисни Run. Пам'ять не очищай, книги не переімпортуй.

Значення вже типові в коді; наявні Secrets мають перевагу:

```text
GROQ_MODEL=openai/gpt-oss-120b
GROQ_FALLBACK_MODEL=qwen/qwen3.8-27b
GROQ_SUMMARY_MODEL=openai/gpt-oss-20b
GROQ_CHAT_REASONING_EFFORT=low
AI_TURN_OUTPUT_TOKEN_BUDGET=2048
```

Лог старту: `Engine=sillytavern-ua-v2 Format=text Upstream=1.19.0`. `SillyTavern prompt` показує кількість реальної історії, включених і доступних example blocks, пам'яті й reference blocks, `post-history instruction True` та оцінку токенів. `thread available` відрізняє наявність state від його `thread injected` у запит. Основна відповідь має `structuredTurn False`. `Book reply replaced with source extract` показує причину заміни непідтвердженої поради; приватний текст і ключі не логуються. Ці записи показують маршрут, а не якість.

Для нового початку без стирання довготривалої пам'яті заверш поточну розмову кнопкою й відкрий «Поговорити» заново. Старі репліки збережені в БД; попередня невдала розмова не перетворюється на нову навчальну картку.

## Перевірка й ліцензія

Після виправлень основний `src/Bot/Bot.csproj` збирається у Release на .NET 10.0.401 без помилок і попереджень. Тести не запускалися й не змінювалися. Гілка не входить у push-тригери тестового workflow; PR у main не створюється.

Ключа Groq та робочої БД у цьому середовищі немає. Користувацька перевірка українського діалогу v1 була невдала. Жива українська якість v2, книжкові поради з фактично імпортованої БД та затримки Telegram тут не перевірені. Вигаданих «успішних відповідей» у звіті немає.

Адаптований upstream-код і preset включено з атрибуцією й AGPL-3.0. `LICENSE` скопійовано з SillyTavern. Команда `/source` доступна без входу в розмову й відкриває вихідний код цієї версії та ліцензію.
