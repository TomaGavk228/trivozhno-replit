## Запуск у наявному Replit

1. Зупини поточний запуск кнопкою Stop.
2. Підтягни гілку через Git/Replit. Якщо працюєш у Shell з уже підключеним репозиторієм:

```bash
git fetch origin
git switch human-chat-v3-research
git pull --ff-only origin human-chat-v3-research
```

Ці команди не відкидають локальні зміни. Якщо Git повідомить про конфлікт або розходження історії, не використовуй reset/force: спочатку збережи локальну роботу.

3. У Secrets установи:

```text
GROQ_MODEL=openai/gpt-oss-120b
GROQ_FALLBACK_MODEL=openai/gpt-oss-120b
GROQ_SUMMARY_MODEL=openai/gpt-oss-20b
AI_INPUT_TOKEN_BUDGET=4800
AI_TURN_OUTPUT_TOKEN_BUDGET=1800
```

Наявний `GROQ_MODEL` у Secrets має перевагу над кодом. Саме оновлення коду не замінить старий Secret з Qwen. Ключі, базу та Telegram-токен залиш свої. Звичайний .env не завантажується застосунком.

4. Натисни Run. Наявний `scripts/run.sh` збирає застосунок і застосовує міграції перед запуском. Цей коміт не додає міграцій; при переході з main потрібна вже наявна у V3 міграція профілю/телеметрії.
5. Заверши поточний чат у Telegram та відкрий «Виговоритися» знову. Не очищай пам'ять: книги, факти та історія збережені.

## Що змінено

- GPT-OSS-120B — основна модель за замовчуванням. Автоматичного переходу на платний сервіс немає.
- Звичайний хід — одна генерація. Книжковий запит потребує другого проходу, обірвана генерація може мати одну додаткову спробу в межах квот і загального тайм-ауту. Мережеві повтори залишаються обмеженими.
- Замість фіксованих 2200 одиниць вхідного контексту використовується бюджет з налаштувань, обмежений квотою мінус генерація та оцінка JSON-схеми.
- До 24 попередніх повідомлень; свіжі цілі обміни отримують місце до старих нотаток. Це максимум, не обіцянка передати всі 24. Дуже довгий останній обмін явно скорочується в контексті, оригінал зберігається.
- 650 одиниць резерву для книжкового доповнення. Бюджет повторно враховується при додаванні уривка.
- Стан має окремі поля прохання, уточнень, дії, реакції та невиконаного. Стан минулої сесії не переноситься як чинне завдання; фактична пам'ять і доступна історія залишаються.
- Профіль змінюється лише за явним загальним проханням про стиль. Модель має надати точну цитату з останнього повідомлення; код перевіряє її наявність і whitelist значення. Це зменшує випадкові записи, але не є гарантією правильного семантичного висновку.
- Бюджет structured generation — 1800 замість 360. Це стеля для всього результату, включно зі службовими полями та reasoning, а не бажана довжина відповіді.
- Немає обрізання reply на 1200 символах. Незавершений результат не відправляється як завершена відповідь. Telegram-розбиття довгого тексту лишається наявним.
- Підсумовування використовує CoveredThroughId і більше не видаляє вихідні повідомлення. Раніше видалені старою версією повідомлення це не відновлює. Наявні команди очищення даних продовжують працювати.
- Промпт спрямовує на зміст, доречну ініціативу, реакцію на уточнення та завершення запиту; без постійних вправ, допиту або порожнього співчуття.

## Безкоштовний Groq

Нових платних залежностей немає. `GROQ_RPM/TPM/RPD/TPD` залишаються локальними межами й мають відповідати фактичним лімітам акаунта Groq; код не може збільшити ліміти провайдера. Більший доступний контекст може витрачати більше токенів за хід. Після відповіді резерв звіряється з usage API. Коли квота вичерпана, бот не купує додаткові токени.
