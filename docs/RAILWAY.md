# Перенесення робочої версії на Railway

Виконуй після перевірки функцій на Replit. Код уже містить Dockerfile і `railway.json`.

1. Створи приватний GitHub-репозиторій із кодом. Додай файли проєкту, включно з конфігурацією, міграціями та `packages.lock.json`. Не додавай Secrets, PDF, дампи, `.dotnet`, `bin`, `obj`.
2. У Railway створи новий проєкт і окремий сервіс PostgreSQL.
3. Додай сервіс застосунку з GitHub-репозиторію. Railway має використати Dockerfile з кореня.
4. У Variables застосунку додай `DATABASE_URL` через посилання на змінну PostgreSQL, наприклад `${{Postgres.DATABASE_URL}}`, якщо сервіс називається `Postgres`. Додай `TELEGRAM_BOT_TOKEN`, `GROQ_API_KEY`, `CONFESSIONS_CHANNEL_ID`.
5. Залиши **одну репліку**, вимкни засинання/Serverless для цього сервісу. Long polling і планувальник мають працювати постійно.
6. Pre-deploy command: `dotnet Bot.dll migrate`. Команда запуску вже в Dockerfile: `dotnet Bot.dll serve`. Healthcheck: `/api/readyz`.
7. Створи робочого Telegram-бота окремо від тестового і додай його до робочого службового каналу з правом публікації.
8. Запусти Deploy, перевір readiness та `/start` у Telegram.

Міграції захищені advisory lock. Сам воркер має окреме блокування: два процеси з одним токеном у тій самій БД не запустяться одночасно. Telegram також повідомляє про конфлікт двох poller. Для оновлення long-polling сервісу використовуй зупинку старого екземпляра перед запуском нового: звичайний rolling overlap може завадити readiness нової версії. Не допускай одночасного production-запуску з Replit і Railway.

## Книги без тестових користувачів

Найпростіший шлях — повторний імпорт власних PDF у чисту робочу базу. Зупини тестового бота на Replit, тимчасово вкажи в `DATABASE_URL` **зовнішній** рядок підключення Railway PostgreSQL (приватна адреса `*.railway.internal` не доступна з Replit), виконай `migrate`, потім `import-books`. Після завершення одразу поверни тестовий `DATABASE_URL` перед натисканням Run.

```bash
bash scripts/bot.sh migrate
bash scripts/bot.sh import-books --path ./data/books
bash scripts/bot.sh list-books
```

Альтернатива — локальний запуск тієї самої команди з робочим DATABASE_URL. PDF не додаються до Docker-образу або Git.

## Диск і резервні копії

Всі постійні записи бота — у PostgreSQL. Локальна файлова система застосунку не використовується для історії чи черг. Увімкни потрібну політику резервних копій у хостингу та зафіксуй її строк. Відновлення має дотримуватися правил `OPERATIONS.md`, щоб не повернути видалені записи.
