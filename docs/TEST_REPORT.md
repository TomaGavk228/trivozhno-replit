# Звіт перевірок — 12 вересня 2026

## Результат

Фінальний прогін: **33 пройшли, 0 помилок, 1 пропущено**. Пропущено навантажувальний тест за останнім рішенням замовника. Час виконання тестів — приблизно 18 секунд без відновлення залежностей і збірки. В архіві є машинний результат `docs/evidence/tests.trx`.

Release publish завершився успішно. У вихідну збірку скопійовані українські ресурси, обидва промпти та міграція. JSON, конфігурація Replit і синтаксис shell-скриптів перевірені. Статичні звернення до українського каталогу не мають відсутніх ключів.

## Середовище і межі

- Linux x86_64, .NET SDK 10.0.401, runtime 10.0.12, EF Core 10.0.9, Npgsql 10.0.3.
- 10 модульних перевірок і 23 інтеграційні сценарії з реально виконуваними SQL, EF-міграціями та обмеженнями таблиць.
- SQL-середовище тут: PostgreSQL 18.3 у WebAssembly **PGlite 0.5.8** через адаптер TCP. Це не перевірка на звичайному сервері PostgreSQL Replit/Railway. Для адаптера вимкнено pooling у тестовому підключенні; код production не використовує PGlite.
- У кожному сценарії створюється окрема схема. Telegram і AI підмінено керованими клієнтами; HTTP-помилки Groq перевірено підміною HTTP handler.
- Жодні реальні повідомлення в Telegram та запити до Groq під час цих тестів не відправлялися.

Перед робочим запуском повтори `bash scripts/test.sh` з `TEST_DATABASE_URL` окремої звичайної PostgreSQL. Не спрямовуй тести на робочу базу.

## Перевірені сценарії

| Група | Що перевірено |
|---|---|
| Навігація | `/start`, текст у меню без AI, нетекстове повідомлення не знищує чернетку, старі кнопки, підтвердження втрати чернетки |
| Чат | Порядок швидких реплік, попередня відповідь у контексті, розділення користувачів, потрібна reply-клавіатура |
| Пам’ять | Збереження при виході, стиснення зі збереженням останніх 10 реплік, збій підсумку не видаляє історію |
| Запізнілі результати | Вихід із чату, очищення пам’яті та видалення профілю під час AI-запиту не повертають старий результат |
| Зізнання | Кілька частин, заміна тексту, подвійне відправлення, канал без профілю й кнопок, повтор відомої відмови |
| Невизначена доставка | `delivery_unknown` не повторюється автоматично після відновлення |
| Настрій | Кілька записів за день, нотатка понад 15 000 символів, повне збереження та розбиття історії |
| Історія | Стабільні сторінки й попередній семиденний період |
| Приватність настрою | Початкове вимкнення, явна згода, виключення нотаток після вимкнення |
| Нагадування | Формат часу, частота, один occurrence, пропуск активного введення, календарний Kyiv-time при переходах DST |
| Видалення | Каскадне очищення профілю, черг та переписки; без зміни повідомлень каналу |
| Відновлення | Збережена чернетка та повернення перерваної AI-задачі до черги; дубль Inbox не створює користувача повторно |
| Помилки | Poison update не блокує іншого користувача; Groq 401, 404/fallback, 429 і 503; Telegram 429 та блокування користувачем |
| Текст | Emoji, комбіновані символи, HTML/Markdown як звичайний текст, незмінність тексту після розбиття |
| Конфігурація | URI з percent-encoded паролем, SSL і channel binding, повідомлення помилки без пароля |
| Модулі | Вимкнення настрою не порушує чат і зізнання |

Окремий запуск зі свідомо недоступною БД завершився штатно з кодом `1`, без секретів у логах. Поведінка при втраті блокування описана в `OPERATIONS.md`; безперервна робота під час втрати БД не обіцяється.

## PDF та пошук

Для імпорту створено оригінальний двосторінковий тестовий PDF: перша сторінка містить текст, друга порожня. Отримано один фрагмент із правильною сторінкою, звіт `partial-no-ocr` і список порожніх сторінок `[2]`. Той самий файл під іншою назвою повернув `duplicate-skipped`; другого джерела не створено. Окремо перевірено сторінки фрагментів на межі сторінок та перекриття.

Пошук перевірено на **15 тематичних перефразуваннях і 5 сторонніх запитах**. Очікуваний фрагмент знайдено для **15/15** тематичних запитів; відхилено **5/5** сторонніх. Детальні номери очікуваних/знайдених сторінок є у TRX.

Це авторські синтетичні речення про тривогу, довіру, самотність, межі та інші теми. Дві книги з ТЗ не були надані: їхній імпорт і якість пошуку на них **не перевірені**. Результат не доводить якість довільних перефразувань. Пошук лексичний із словником форм/синонімів і BM25, без embeddings. Після додавання PDF перевір його власними запитами через `search-books`.

## Навантаження

Фінальний прогін пропускає цей тест за проханням замовника. Раніше розпочата спроба в адаптері PGlite завершилася помилкою протоколу `portal cannot be run` та вичерпанням бюджету тесту; успішного результату вона не дала. Її не повторювали. Причину на звичайному PostgreSQL не досліджували.

Тому **немає підтверджених значень пропускної здатності, p95 чи RAM для 1000 користувачів**. Початкова конфігурація має двох AI-воркерів і обмежену чергу, але це не обіцянка продуктивності. Код опційного тесту залишено для подальшого запуску на окремій звичайній PostgreSQL:

```bash
RUN_LOAD_TEST=1 bash scripts/test.sh --filter ThousandAcceptedUpdates
```

## Що ще потребує реального середовища

1. Імпорт архіву й Run у власному Replit, включно з доступністю ICU, NuGet та зовнішньої мережі.
2. Справжній Telegram: права бота в службовому каналі, отримання updates, надсилання, тривалість очікування та нагадування в реальному часі.
3. Невеликий `bash scripts/bot.sh groq-smoke --live`, доступність моделей і фактичні квоти власного Groq-акаунта.
4. Якість живої переписки: коротка репліка, довгий текст, бажання виговоритися без порад, прохання поради, гумор, виправлення спогаду, питання «звідки це?», прохання видати себе за людину. Fake-тести не оцінюють природність відповідей.
5. Звичайна PostgreSQL, конкурентна робота й advisory lock двох процесів; Docker build і розгортання Railway. Тут Docker-образ не запускався.
6. Власні PDF, правила резервних копій і доступна політика хостингу. Вибіркове відновлення персонального backup після видалень у цій версії не реалізовано; задокументовано відновлення з чистої БД.

Код підготовлено для тестового запуску. Робоче розгортання у сторонніх акаунтах ще не виконане.
