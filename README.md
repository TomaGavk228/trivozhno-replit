# Telegram-бот «Тривожно» — просте ядро переписки

Гілка: `feat/chat-reset-2026-10-05`. Базова схема: **промпт + приклади людської мови + останні повідомлення поточної розмови → один текстовий виклик Groq**.

Прибрано попередні планувальники, адаптер SillyTavern, Character Card, PHI, автоматичні профілі й підсумки, каталоги цікавинок/фільмів, пошук книжок для відповіді, перевірки та переписування реплік, підміни уривками й заготовлене привітання. Першу репліку теж генерує модель.

Telegram-меню, зізнання, щоденник настрою, нагадування, об’єднання швидких повідомлень, черги та доставка залишились. Схема PostgreSQL сумісна з попередньою версією: нова гілка не видаляє дані. Старі підсумки, профілі, записи настрою та книжки у контекст чату не потрапляють. Між різними сесіями пам’ять на цьому етапі не переноситься.

## Запуск на існуючому Replit

Зупини поточний Run. У Shell з кореня проєкту:

```bash
git fetch origin
git switch --track origin/feat/chat-reset-2026-10-05
bash scripts/run.sh
```

Якщо локальна гілка вже є, використовуй `git switch feat/chat-reset-2026-10-05` та `git pull --ff-only`. Якщо Git повідомляє про незбережені зміни, збережи їх перед перемиканням; примусове скидання не потрібне.

Run залишається `bash scripts/run.sh`: зафіксовані залежності, Release-збірка, наявні міграції та запуск. Потрібні Secrets: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `GROQ_API_KEY`; для зізнань — `CONFESSIONS_CHANNEL_ID`. Приклади транспортних налаштувань є у [.env.example](.env.example). `.env` автоматично не читається.

## Де підлаштовувати розмову

| Файл | Що змінює |
|---|---|
| [prompt.txt](src/Bot/Resources/Chat/prompt.txt) | Поведінка, мова, довжина та формат Telegram-переписки |
| [examples.json](src/Bot/Resources/Chat/examples.json) | Короткі цитати відкритих українських обговорень; можна прибирати й додавати |
| [generation.json](src/Bot/Resources/Chat/generation.json) | Модель, температура, reasoning, вихідний бюджет і обсяг історії |

Зміни читаються перед наступним повідомленням. У логах є шлях активної папки та SHA конфігурації. Інструкція для редагування й походження матеріалів: [docs/CHAT_CONTENT.md](docs/CHAT_CONTENT.md).

Поведінкову основу адаптовано з обраного користувачем форумного промпту. Це досвід автора допису, а не доказ гарантованої якості. Приклади взято з публічної людської переписки на r/Ukraine_UA, з джерелом для кожного фрагмента; нових вигаданих діалогів немає. Приватна переписка користувача не публікується. Якість конкретної моделі та української переписки потребує живого перегляду користувачем; успішна збірка цього не доводить.

## Технічні межі

- Відповідь генерується одним викликом; транспорт може повторити HTTP 429/5xx на тій самій моделі. Автоматичної зміни моделі немає.
- Показується лише завершений текст. Обрізана відповідь не надсилається; бот повідомляє про помилку.
- У контексті лише поточна сесія та реально доставлені відповіді. За браку бюджету прибираються найстаріші обміни; поточне повідомлення зберігається повністю.
- Книжки зберігаються в базі та доступні оператору для імпорту/пошуку. У цьому першому етапі вони не є джерелами відповідей моделі.
- Автоматичні тести не запускались і їхній код не змінювався. Історичний проєкт тестів стосується прибраної архітектури й не входить до рішення цієї гілки. Збірка застосунку: `bash scripts/dotnet.sh build src/Bot -c Release`.
