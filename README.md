# Telegram-бот «Тривожно» — тестовий запуск на Replit

Оновлення AI-діалогу 19.09: [що змінено і як запустити для ручної перевірки](docs/CHAT_UPDATE_2026_09_19.md).

Готовий C#-проєкт із чатом через Groq, пам’яттю між сесіями, анонімними зізнаннями, щоденником настрою, нагадуваннями та очищенням даних. Спочатку запусти окремого тестового бота на Replit. Для Railway підготовлено Dockerfile та конфігурацію, але робоче розгортання ще не виконане.

## 1. Що потрібно підготувати

| Налаштування | Звідки взяти |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Створи **окремого тестового бота** командою `/newbot` у [BotFather](https://t.me/BotFather). Збережи виданий токен. |
| `GROQ_API_KEY` | Створи ключ у [кабінеті Groq](https://console.groq.com/keys). |
| `CONFESSIONS_CHANNEL_ID` | Числовий ID приватного службового каналу, зазвичай починається на `-100`. |
| `DATABASE_URL` | Підключення до **тестової PostgreSQL**, доступної з Replit. |

У Telegram створи приватний службовий канал. Додай тестового бота його адміністратором і дозволь публікацію повідомлень. Публічний канал для цього проєкту не потрібний: власник переносить відібрані зізнання вручну.

Як отримати ID службового каналу без сторонніх ботів: відкрий повідомлення каналу в Telegram і скопіюй посилання. Для приватного каналу воно часто має вигляд `https://t.me/c/1234567890/42`. Тоді ID — `-1001234567890`. Перевір саме свій канал. Якщо посилання іншого формату, не вгадуй ID — скористайся способом із Telegram Bot API в `docs/OPERATIONS.md`.

Не вставляй ключі в код, Git, README або повідомлення чату. Додавай їх у Secrets потрібного середовища.

## 2. Імпорт ZIP у Replit

1. Завантаж архів проєкту з цієї розмови.
2. Відкрий [replit.com/import](https://replit.com/import).
3. Обери **ZIP**, завантаж архів і натисни **Import**.
4. Відкрий редактор проєкту. У його корені мають бути `README.md`, `global.json`, `src`, `scripts`, `replit.nix`.
5. Якщо імпортер створив зайвий рівень папки, перенеси вміст `trivozhno` у корінь або задай відповідну робочу папку для Run.

Replit офіційно підтримує ZIP та імпорт із GitHub. Під час імпорту дані бази й секрети не переносяться; міграція коду за участю Agent може витрачати його кредити. Цей проєкт уже містить код, тож для звичайного запуску його не потрібно генерувати заново. [Документація імпорту](https://docs.replit.com/build/import-from-providers).

## 3. Тестова база PostgreSQL

У редакторі Replit відкрий **Tools → Database → Development Database → Settings**. За поточною документацією Replit застосунки мають базу за замовчуванням; у Settings доступні дані підключення. Знайди значення `DATABASE_URL` для Development Database. Якщо його вже додано середовищем, повторно створювати Secret з тією ж назвою не потрібно. [База Replit](https://docs.replit.com/features/data-and-storage/sql-database), [підключення](https://docs.replit.com/features/data-and-storage/connection-details).

Якщо конкретний проєкт не має підключення, скористайся створенням Development Database у доступному інтерфейсі Replit або підключи окрему PostgreSQL. Потрібне звичайне PostgreSQL URI/ADO-підключення, не адреса HTTP Data API і не старе Key-Value сховище Replit.

Приклад формату, **не готові реквізити**:

```text
postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require
```

Використовуй SSL-режим, який вказав постачальник бази. URI-пароль зі спеціальними символами має бути percent-encoded. Підтримуються `sslmode`, `sslrootcert`, `connect_timeout`, `application_name`, `channel_binding`. Невідомий параметр дає зрозумілу помилку без показу пароля.

## 4. Secrets і перший запуск

У **Tools → Secrets** додай чотири значення з таблиці в розділі 1. Решта налаштувань уже мають типові значення; повний перелік — у `.env.example`. Звичайний `.env` застосунок автоматично не читає.

Натисни **Run**. Перший запуск може тривати кілька хвилин:

1. Скрипт знайде сумісний .NET SDK або завантажить SDK 10.0.401.
2. Відновить зафіксовані залежності й збере застосунок.
3. Окремою командою застосує міграції бази.
4. Запустить бота на порту 8080.

Власний комп’ютер виконує лише роль доступу до редактора — збірка відбувається в Replit.

Якщо Run не підхопив команду, встанови її в **Workflows**:

```bash
bash scripts/run.sh
```

У Preview відкрий `/api/readyz`. Відповідь `{"status":"ready"}` означає, що база доступна і воркер запущений. `/api/healthz` перевіряє лише живий процес. Це службові адреси, а не вебінтерфейс бота. [Конфігурація Replit](https://docs.replit.com/features/project-setup/configuration).

Потім відкрий тестового бота в Telegram і надішли `/start`.

Replit Run використовується тут для тестів. Коли процес зупинено, бот і нагадування не працюють. Для постійної роботи передбачено Railway.

## 5. Перевірка власноруч

| Дія | Що має відбутися |
|---|---|
| `/start`, потім звичайний текст у меню | Меню, без запиту до ШІ |
| «Виговоритися», кілька повідомлень, завершення | Послідовні відповіді, тільки кнопка завершення внизу; пам’ять зберігається |
| Два Telegram-користувачі | Окремі розмови, чернетки та записи |
| Зізнання з кількох повідомлень | Підтвердження без повторного показу всього тексту; у каналі текст і номер без профілю |
| Два записи настрою за день, довга нотатка | Обидва записи збережено; історія ділиться на частини |
| Нагадування на найближчий час | Одне нагадування поза активним введенням |
| Stop, потім Run | Поточна чернетка та пам’ять збережені |
| Очистити пам’ять | Переписку й підсумок видалено, настрій лишився |
| Видалити дані | Профіль і записи видалено; повідомлення службового каналу лишилися |

## 6. Книги

PDF не входять до архіву. Завантаж власні примірники у `data/books` і в Shell виконай:

```bash
bash scripts/bot.sh import-books --path ./data/books
bash scripts/bot.sh list-books
```

Повторний ідентичний PDF пропускається за SHA-256. Звіт містить кількість сторінок, фрагментів і сторінки без тексту. Код завершення `2` при частковому імпорті означає, що деякі сторінки не прочитано; OCR не виконується. Після успішного імпорту фрагменти зберігаються в PostgreSQL і PDF не потрібні під час роботи.

```bash
bash scripts/bot.sh search-books --query "Боюся помилитися"
bash scripts/bot.sh deactivate-book 1
```

Пошук лексичний: нормалізація, точний словник українських форм і тематичних синонімів, BM25-ранжування кандидатів. Це не семантичний пошук. Без релевантних фрагментів або без книг бот веде звичайну переписку. Результати перевірок та їх межі — у `docs/TEST_REPORT.md`.

## 7. Тести й обслуговування

Без підключеної тестової БД запускаються модульні тести, інтеграційні позначаються пропущеними:

```bash
bash scripts/test.sh
```

Для інтеграційних тестів додай `TEST_DATABASE_URL` **окремої порожньої тестової PostgreSQL**. Тести створюють і видаляють власні схеми; не використовуй робочу БД.

```bash
bash scripts/test.sh
RUN_LOAD_TEST=1 bash scripts/test.sh --filter ThousandAcceptedUpdates
```

Навантажувальний тест використовує підміни AI й Telegram, не витрачає Groq. Окремий реальний запит Groq:

```bash
bash scripts/bot.sh groq-smoke --live
```

Він використовує невелику частину квоти. Команди перегляду черг, ручного розв’язання невизначеної доставки, приватність та відновлення описані в `docs/OPERATIONS.md`.

## 8. Railway — коли завершиш тестування

Дивись `docs/RAILWAY.md`. Для перенесення не потрібно переписувати бота. Потрібні новий токен робочого бота, робоча PostgreSQL, ключ Groq та ID службового каналу. Тестових користувачів переносити не потрібно.

Пробний Railway — **до 30 днів або до витрачання $5 кредиту**; у неперевірених акаунтів можливі мережеві обмеження. Не розраховуй на гарантовані 30 днів незалежно від споживання. [Умови пробного періоду](https://docs.railway.com/pricing/free-trial).

## 9. Версії та межі перевірки

Обрано .NET 10 LTS замість базового .NET 8 з ТЗ: підтримка .NET 8 завершується в листопаді 2026, .NET 10 підтримується до листопада 2028. Поведінку функцій збережено. SDK, EF Core, Npgsql та пакети тестів зафіксовані; точні транзитивні залежності — у `packages.lock.json`. [Життєвий цикл Microsoft](https://learn.microsoft.com/en-us/dotnet/core/releases-and-support).

Реальне підключення до твого Replit, Telegram, Groq і службового каналу потребує твоїх Secrets. Воно не виконувалося під час підготовки архіву. Docker-конфігурацію Railway підготовлено для наступного етапу. Детальний звіт — у `docs/TEST_REPORT.md`.
