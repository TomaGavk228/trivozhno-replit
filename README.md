# Telegram-бот «Тривожно» — просте ядро переписки

Гілка: `feat/gemini-3-5-flash-lite-2026-10-06`. Базова схема: **промпт + приклади + поточна переписка + пам’ять → один виклик Google Gemini 3.5 Flash-Lite з відповіддю та оновленням пам’яті**. Налаштування API й діагностика: [docs/GEMINI_SETUP.md](docs/GEMINI_SETUP.md).

Прибрано попередні планувальники, адаптер SillyTavern, Character Card, PHI, каталоги цікавинок/фільмів, пошук книжок для відповіді, перевірки та переписування реплік, підміни уривками й заготовлене привітання. Першу репліку теж генерує модель.

Telegram-меню, зізнання, щоденник настрою, нагадування, об’єднання швидких повідомлень, черги та доставка залишились. Схема PostgreSQL сумісна з попередньою версією: нова гілка не видаляє дані. Пам’ять повернено: старі підсумки, явно висловлені уподобання, вибрані цитати попередніх сесій та нові факти використовуються в чаті. Короткий стан розмови оновлюється тією самою генерацією, що й відповідь. Нові міграції не потрібні. Записи настрою й книжки поки не додаються до контексту.

## Запуск на існуючому Replit

Зупини поточний Run. У Shell з кореня проєкту:

```bash
git fetch origin
git switch --track origin/feat/gemini-3-5-flash-lite-2026-10-06
bash scripts/run.sh
```

Якщо локальна гілка вже є, використовуй `git switch feat/gemini-3-5-flash-lite-2026-10-06` та `git pull --ff-only`. Якщо Git повідомляє про незбережені зміни, збережи їх перед перемиканням; примусове скидання не потрібне.

Перед запуском додай у Replit Secrets `GEMINI_API_KEY` з Google AI Studio та зміни `AI_PROVIDER` на `gemini`. Run залишається `bash scripts/run.sh`: зафіксовані залежності, Release-збірка, наявні міграції та запуск. Інші потрібні Secrets: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`; для зізнань — `CONFESSIONS_CHANNEL_ID`. Приклади налаштувань є у [.env.example](.env.example). `.env` автоматично не читається.

## Де підлаштовувати розмову

| Файл | Що змінює |
|---|---|
| [prompt.txt](src/Bot/Resources/Chat/prompt.txt) | Поведінка, мова, довжина та формат Telegram-переписки |
| [examples.txt](src/Bot/Resources/Chat/examples.txt) | Короткі вигадані діалоги у манері Артема; звичайний текст із позначками «Людина» і «Друг» |
| [generation.json](src/Bot/Resources/Chat/generation.json) | Модель, температура, reasoning, вихідний бюджет, обсяг історії й бюджет пам’яті |

Зміни читаються перед наступним повідомленням. У логах є шлях активної папки та SHA конфігурації. Інструкція для редагування й походження матеріалів: [docs/CHAT_CONTENT.md](docs/CHAT_CONTENT.md).

Поведінкову основу адаптовано з обраного користувачем форумного промпту. Це досвід автора допису, а не доказ гарантованої якості. На прохання Артема приклади замінено новими вигаданими діалогами за його манерою: короткі відгуки, увага до деталей, ситуативний гумор і дружня допомога. Це стилізація, а не дослівні приватні цитати або перевірені психологічні рекомендації. Дружня манера й короткі репліки зберігаються також у відповідях на прохання допомогти. Якість конкретної моделі та української переписки потребує живого перегляду користувачем; успішна збірка цього не доводить.

## Технічні межі

- Відповідь генерується одним викликом; транспорт може повторити HTTP 429/5xx на тій самій моделі. Автоматичної зміни моделі немає.
- Gemini використовує рідний `models.generateContent`, `systemInstruction`, ролі `user/model`, `maxOutputTokens`, thinking `MINIMAL` і JSON-схему в `generationConfig.responseFormat.text`. Результат перевіряється локально; додаткового виклику для ремонту JSON немає.
- `GEMINI_MAX_CONCURRENCY=1` обмежує паралельні HTTP-запити. При 429 враховується `Retry-After` або Google `RetryInfo` та спільна пауза. Старі квоти Groq не застосовуються до Gemini. Фактичні ліміти проєкту перевіряються в Google AI Studio; новий API-ключ того самого проєкту їх не скидає. Статистика записується як `google/gemini-3.5-flash-lite` у наявну таблицю без нової міграції.
- Показується лише завершений текст. Обрізана відповідь не надсилається; бот повідомляє про помилку.
- У контексті поточна сесія, реально доставлені відповіді та обмежений блок пам’яті. За браку бюджету пам’ять скорочується, найстаріші обміни відкидаються; поточне повідомлення зберігається повністю. JSON-схема також враховується в бюджеті.
- Нові факти зберігаються лише з дослівною цитатою поточного користувацького повідомлення. Окремих AI-викликів для пам’яті немає. У Telegram надсилається лише поле `reply`; стан розмови й факти залишаються в базі. Очищення пам’яті скидає всі ці дані.
- Книжки зберігаються в базі та доступні оператору для імпорту/пошуку. У цьому першому етапі вони не є джерелами відповідей моделі.
- Автоматичні тести не запускались і їхній код не змінювався. Історичний проєкт тестів стосується прибраної архітектури й не входить до рішення цієї гілки. Збірка застосунку: `bash scripts/dotnet.sh build src/Bot -c Release`.
